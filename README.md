# Vault — мультичейн крипто-кошелёк

Веб-кошелёк в духе Trust Wallet: один seed (12 слов) → адреса в нескольких сетях,
просмотр баланса, отправка транзакций. Всё хранение ключей и подпись происходят
**только в браузере** — приватные ключи никогда никуда не отправляются.

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес из терминала (обычно `http://localhost:5173`).

Для продакшен-сборки:
```bash
npm run build
npm run preview
```

## Что поддерживается

- **Сети:** Ethereum, BNB Smart Chain, Polygon, Arbitrum One (все EVM — один и тот же
  адрес), плюс Bitcoin (native SegWit / bech32).
- **Создание и импорт** кошелька по BIP-39 seed-фразе (12 слов).
- **Деривация ключей:** EVM — `m/44'/60'/0'/0/0`, Bitcoin — `m/84'/0'/0'/0/0`.
- **Баланс:** EVM — через публичные RPC (publicnode.com), Bitcoin — через
  Blockstream API.
- **Отправка:** нативная монета сети (ETH/BNB/POL и т.д.) для EVM; полноценная
  сборка и подпись Bitcoin-транзакции (выбор UTXO, сдача, комиссия по sat/vB) для BTC.
- **Хранение:** seed-фраза шифруется паролем (AES-GCM + PBKDF2, 250k итераций) и
  лежит в `localStorage` в зашифрованном виде.

## Чего нет (и на что обратить внимание перед реальным использованием)

Это рабочий прототип, а не аудированный продукт. Прежде чем доверять ему реальные
средства, стоит закрыть следующие пробелы:

- **Нет отправки токенов** (ERC-20/BEP-20/SPL и т.д.) — только нативная монета сети.
- **Нет истории транзакций** — публичные RPC не отдают её без индексатора;
  сейчас просто даётся ссылка на блокэксплорер.
- **RPC/API — публичные и бесплатные** (publicnode.com, blockstream.info). Для
  продакшена лучше использовать платных провайдеров (Alchemy, Infura, QuickNode) со
  своими ключами и rate limit.
- **Нет аудита безопасности.** Код не проверялся сторонним аудитором — стандартная
  практика перед тем, как кошелёк начинает работать с реальными деньгами.
- **localStorage** уязвим к XSS: любой внедрённый в страницу JS теоретически может
  прочитать зашифрованный vault (хотя без пароля расшифровать его нельзя за разумное
  время). Для более серьёзной защиты стоит рассмотреть аппаратные кошельки как
  подписывающий бэкенд вместо хранения ключей в браузере.
- **Нет проверки чексуммы/фишинговых адресов**, нет поддержки ENS-имён.
- **Комиссии EVM** используют базовую оценку (`gasLimit = 21000`) — подходит только
  для простых переводов нативной монеты, не для контрактов.

## Структура проекта

```
src/
  lib/
    chains.js         — конфигурация сетей (RPC, chainId, символы)
    crypto.js          — шифрование/расшифровка seed-фразы (Web Crypto)
    storage.js           — localStorage-обёртка для зашифрованного vault
    walletCore.js          — деривация ключей, оценка комиссии, отправка транзакций
  components/
    Onboarding.jsx          — создание/импорт кошелька
    BackupSeed.jsx           — подтверждение сохранения seed-фразы
    SetPassword.jsx           — установка пароля шифрования
    Unlock.jsx                  — экран разблокировки
    Dashboard.jsx                 — список активов и балансов
    SendSheet.jsx                   — отправка транзакции
    ReceiveSheet.jsx                  — QR-код и адрес для получения
    SettingsSheet.jsx                   — показать seed, заблокировать, удалить кошелёк
```
